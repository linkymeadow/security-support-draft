# 보안 지침에 대한 제안

보안 지침에 담으면 좋을 내용과 예시를 모은 초안입니다.\
지침을 만드는 분들이 참고하고 의견을 보탤 수 있도록 정리했습니다.

보안 도구나 플랫폼을 직접 만들거나 운영하지 않으며, 상세 구현은 다루지 않습니다.

의견이나 문서 수정안을 제안하려면 [기여 안내](CONTRIBUTING.md)를 참고해 주세요.

## 문서 목차

지침에 담을 내용과 설명 방식, 자료를 관리하고 활용할 때의 고려사항을 주제별로 나누었습니다.

- [제안이 필요한 배경](proposal/background.md)

  AI로 달라진 개발·공격 환경과 보안 문제에 대응하기 어려운 이유를 살펴봅니다.

- [익숙한 서비스 이름에서 시작하는 보안 안내](proposal/service-environment-guidance.md)

  업체·제품명처럼 익숙한 이름에서 출발해, 사용 환경과 관리 범위를 알아보는 안내를 제안합니다.

- [보안 용어를 이해하고 다음 행동을 알 수 있도록](proposal/plain-language-guidance.md)

  어려운 말을 풀어 설명하고, 확인할 일과 담당자에게 물어볼 내용을 함께 안내하는 예시입니다.

- [보안 공지를 확인과 조치로 이어갈 수 있도록](proposal/security-notice-guidance.md)

  공지가 내 서비스에도 해당하는지, 무엇을 조치했는지 확인하는 데 필요한 내용을 정리했습니다.

- [담당자가 바뀌어도 보안 점검을 이어갈 수 있도록](proposal/continuous-security-review.md)

  인력교체와 시스템 파악의 어려움 속에서 AI·자동화로 점검을 돕고, 확인 기록을 이어가는 방안을 다룹니다.

- [보안 조치의 이유를 쉽게 설명할 수 있도록](proposal/security-control-reasons.md)

  동료와 의사결정권자에게 보안 조치의 이유, 필요한 시간과 인력을 설명하는 문구 예시입니다.

- [개인정보 보호, 무엇을 어떻게 해야 하는지 알 수 있도록](proposal/privacy-guidance.md)

  개인정보의 보관·조회·삭제 사례와 사람과 AI가 함께 확인할 점검표의 구성을 다룹니다.

- [권한에 맞는 정보와 기능만 이용할 수 있도록](proposal/access-control-guidance.md)

  비로그인 방문자부터 AI 에이전트까지, 볼 수 있는 정보와 할 수 있는 일을 구분하는 사례입니다.

- [AI 에이전트가 허용된 자료와 작업 범위를 넘지 않도록](proposal/agent-scope-guidance.md)

  업무에 필요한 도구와 권한만 제공하고, 외부 자료의 지시나 파일 전달로 허용 범위를 넘지 않도록 확인할 내용을 다룹니다.

- [문제를 분석하고 이상 징후를 알아차리기 위한 기록](proposal/logging-guidance.md)

  남겨야 할 기록과 빼야 할 정보, 이상 징후 확인과 AI 분석 시 주의할 점을 정리했습니다.

- [보안 점검 자료를 함께 관리하고 내부망에서도 활용할 수 있도록](proposal/shared-security-data.md)

  기여 내용의 검토, 자료 관리에 필요한 인력·비용, 필요한 파일만 받아 내부망에서 쓰는 방안을 다룹니다.

- [취약점 점검 가이드의 악용 위험](proposal/dual-use-risk.md)

  점검 자료가 공격에도 쓰일 수 있다는 점을 고려해, 어디까지 설명하고 공개할지 살펴봅니다.

## 목적을 다한 뒤에는

제안의 목적을 다하면 저장소를 아카이브해 기록으로만 남깁니다. 이후에는 문서 갱신이나 새로운 의견·수정 요청의 검토를 하지 않습니다.

## 보증 부인

이 자료는 보안 지침에 담을 내용을 제안하는 초안입니다.

내용의 정확성·완전성·최신성이나 적용 결과를 보증하지 않습니다.\
실제 적용 전에는 해당 환경에 맞는 검토가 필요합니다.

저장소 운영자·작성자·기여자는 이 자료의 이용 또는 이용 불가로 발생하는 손해에 대해 책임을 지지 않습니다.
