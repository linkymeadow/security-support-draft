# 담당자가 바뀌어도 보안 점검을 이어갈 수 있도록

서비스를 처음 만든 사람의 기억과 경험에만 의존하면, 담당자가 바뀌거나 관리할 시스템이 늘어날 때 보안 점검이 끊길 수 있습니다. 내부 구성을 충분히 알지 못한 채 기능이 동작하는지만 확인하고 운영하는 경우에도 새로 알려진 취약점이 어디에 해당하는지 판단하기 어렵습니다.

AI와 자동화를 활용해 매일 새로 발표되거나 수정된 보안 공지를 확인하고, 운영 중인 전체 시스템과 대조하는 지원을 제안합니다. 사람이 공지마다 같은 내용을 처음부터 조사하는 부담을 줄이고, 확인과 조치가 필요한 부분에 집중할 수 있도록 돕자는 취지입니다.

## 시스템을 만들었다고 모든 구성을 알고 있는 것은 아닙니다

시스템 구축(SI)과 운영·유지보수(SM) 업무에서는 여러 시기에 서로 다른 업체나 개발자가 만든 시스템을 맡을 수 있습니다. 퇴사·담당 업무 변경이나 계약 종료로 사람이 바뀌면, 어떤 프로그램을 사용했고 왜 특정 설정을 적용했는지 충분히 전달받지 못할 수도 있습니다. 한 사람이 관리 대상 전체를 파악하기 어려운 상황도 생깁니다.

처음 개발한 사람이 남아 있더라도, 가져다 쓴 프로그램의 내부 동작이나 이후에 바뀐 구성까지 모두 기억하고 검토하기는 어렵습니다. 누가 무엇을 알고 있는지에 기대기보다, 현재 시스템이 어떤 프로그램과 설정으로 동작하는지 확인할 수 있는 자료가 필요합니다.

AI에게 코드를 작성하게 하는 개발 방식에서도 비슷한 문제가 생길 수 있습니다. 기능이 작동하는지만 확인하고 내부 구현을 살펴보지 않았다면, 제작자도 어떤 프로그램 부품을 사용하고 어떤 권한을 허용했는지 모를 수 있습니다. 내부가 어떻게 돌아가는지 알지 못하는 상태로 서비스를 운영하게 되는 것입니다.

이런 상황에서 새 보안 공지가 나올 때마다 관련 프로그램을 찾아내고 모든 운영 시스템과 비교하는 일을 사람의 기억과 수작업에만 맡기기는 어렵습니다. 담당자가 바뀌거나 내부 지식이 부족해도 반복해서 확인할 수 있는 지원이 필요한 이유입니다.

## 매일 새 공지를 전체 운영 시스템과 대조합니다

여기서 매일 점검한다는 것은 새로 발표되거나 수정된 보안 공지를 확인하고, 관리 중인 전체 시스템 목록과 구성 정보를 비교해 후속 확인 대상을 정리한다는 뜻입니다. 코드나 설정을 바꾸지 않은 시스템도 새로 알려진 취약점의 영향을 받을 수 있으므로, 최근에 개발하거나 수정한 서비스만 살펴봐서는 확인 범위가 빠질 수 있습니다.

자동화 도구는 공지 수집과 반복 비교를 맡고, AI는 공지의 의미와 적용 조건을 풀어 설명하며 어떤 시스템에서 무엇을 더 확인해야 할지 정리하도록 도울 수 있습니다. 역할을 다음처럼 나누어 생각할 수 있습니다.

1. 새 공지와 변경된 안내를 확인합니다. 공식 출처와 확인 날짜를 함께 남깁니다.
2. 운영 시스템 목록과 비교합니다. 사용 중인 프로그램과 버전(출시·수정 상태를 구분하는 번호), 기능·설정이 공지의 조건과 관련 있는지 살펴봅니다.
3. 확인할 대상을 정리합니다. 관련 시스템과 판단 근거, 아직 모르는 부분을 묶어 담당자에게 전달합니다.
4. 후속 확인을 이어갑니다. 담당자가 확인하거나 조치한 결과를 남기고, 공지나 시스템 구성이 바뀌면 다시 살펴봅니다.

예를 들어 여러 사이트가 같은 프로그램을 사용한다면, 공지 하나를 확인할 때 관련 사이트를 함께 살펴볼 수 있어야 합니다. 최근에 작업한 사이트 한 곳만 확인하고 오래된 사이트는 빠뜨리는 일을 줄이려는 것입니다. 목록에 없는 시스템은 비교 대상에서도 빠질 수 있으므로, 운영을 시작하거나 끝낸 시스템과 구성 변경도 목록에 반영해야 합니다.

매일 반복하는 점검은 기본 일정으로 두되, 중요한 공지를 이미 확인했다면 다음 정기 점검까지 기다리지 않고 필요한 확인을 시작할 수 있어야 합니다.

## 모르는 부분과 확인 기록을 다음 담당자에게 남깁니다

AI도 자료에 없는 내부 구성을 정확히 알 수는 없습니다. 사용 프로그램이나 버전이 기록되지 않았거나 자료가 오래됐다면, "문제없음"으로 처리하지 않고 "추가 확인 필요"로 남깁니다. 그럴듯한 값을 채워 넣기보다 무엇을 모르고 누구에게 확인해야 하는지 정리하는 역할이 필요합니다.

비교 결과에는 어떤 공지와 구성 정보를 사용했는지, 언제 확인했는지, 무엇이 아직 확인되지 않았는지를 남깁니다. 한 시스템을 확인했다고 다른 시스템까지 조치된 것으로 보거나, AI가 제시한 대응 방법을 실제로 적용한 결과처럼 기록하지 않습니다. 이번 공지에 해당하지 않는다는 판단도 시스템 전체가 안전하다는 의미로 표시하지 않습니다.

담당자가 바뀌면 이 자료와 함께 확인 중인 항목, 이미 조치한 내용, 남은 작업과 다음 확인 시점을 넘겨줄 수 있어야 합니다. 새 담당자는 이전 사람에게 같은 질문을 반복하기보다 기록을 바탕으로 필요한 확인을 이어갑니다. 확인할 사람이 정해지지 않은 항목도 그대로 드러내어 책임자를 배정할 수 있게 합니다.

실제 설정 변경이나 업데이트는 담당자가 근거와 서비스에 미칠 영향을 확인한 뒤, 조직이 허용한 절차에 따라 진행합니다. 이 지원의 목적은 반복 조사와 비교의 부담을 줄이면서 확인되지 않은 부분을 드러내고, 인력이나 환경이 바뀌어도 점검과 조치를 이어갈 수 있게 하는 것입니다.
