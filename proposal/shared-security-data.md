# 보안 점검 자료를 함께 관리하고 내부망에서도 활용할 수 있도록

보안 점검 자료는 한 번 공개하는 것으로 끝나지 않습니다. 새로운 문제가 알려지면 내용을 보완하고, 잘못된 설명은 바로잡아야 합니다. 공개 기여를 검토 없이 받아들이면 잘못된 정보가 점검 기준으로 쓰일 수 있습니다. AI가 자료 속 지시를 따라 판단을 바꾸거나 허용되지 않은 행동을 하도록 유도하는 "프롬프트 인젝션"도 살펴봐야 할 위험입니다.

신뢰할 수 있는 기관이 책임을 맡고, 공개 저장소(자료와 수정 이력을 함께 관리하는 공간)에서 누구나 개선을 제안하되 검토를 거친 자료를 배포하는 방식을 제안합니다. 외부 인터넷에 접속하기 어려운 조직도 이를 파일로 받아 활용하고 갱신할 수 있어야 합니다. 검토부터 배포·갱신까지 이어갈 인력과 비용, 담당 업체가 바뀌어도 유지되는 관리 체계를 함께 준비하면 좋겠습니다.

이 문서는 이러한 지원을 만들 주체를 위한 제안입니다. 이 저장소에서 점검 자료를 직접 구축하거나 배포 서비스를 운영하겠다는 계획은 아닙니다.

## 누구나 제안하고, 담당자가 검토합니다

운영자·개발자·보안 전문가와 실제 이용자 누구나 오류나 빠진 내용을 제안할 수 있게 합니다. 어려운 표현을 쉽게 고치거나 특정 환경에서는 설명이 맞지 않는다고 알리는 것도 기여입니다. PR(수정한 내용을 검토해 달라는 요청)과 토론 공간에서 개선 이유와 근거를 함께 남깁니다.

책임 기관은 검토·승인·정정·갱신을 맡을 사람을 지정합니다. 제안이 들어왔다고 바로 기존 자료에 합치지 않고, 작성자 외의 검토자가 내용을 확인하도록 합니다.

PR을 검토하고 최종 병합(제안한 변경을 기존 자료에 합치는 일) 여부를 결정하는 사람은 가능한 한 개발과 보안 지식을 함께 갖추면 좋겠습니다. 문장뿐 아니라 내용을 실제로 적용했을 때 어떻게 작동하고 어떤 위험이 생길지 판단해야 하기 때문입니다. 자신의 전문 범위를 벗어난 내용은 해당 분야 전문가의 검토를 받은 뒤 반영 여부를 결정합니다.

검토할 때는 다음 내용을 살펴봅니다.

- 근거와 확인 날짜가 분명하고, 어떤 제품·환경에 해당하는지 알 수 있는가?
- 이용자가 설명을 읽고 무엇을 확인하거나 조치해야 하는지 이해할 수 있는가?
- 개인정보·비밀번호·비공개 내부 정보가 섞여 있거나, 공격에 바로 사용할 자료를 모으는 내용은 없는가?
- AI가 원래 지시를 무시하거나 점검을 핑계로 허용되지 않은 행동을 하도록 유도하지는 않는가?

AI가 작성한 자료도 같은 검토를 거칩니다. 자동 검사에 통과했다는 이유만으로 반영하지 않으며, 근거가 부족하거나 검토할 사람이 없다면 보류합니다. 검토 중인 제안과 배포할 자료를 구분하고, 누가 어떤 근거로 반영했는지와 변경 내용을 남깁니다. 이 기록이 있어야 다음 담당자도 결정 이유를 알 수 있습니다.

검토를 마쳤다는 표시는 자료의 확인 상태를 뜻하며, 이를 사용하는 시스템의 안전성을 인증하는 것은 아닙니다.

### AI가 참고할 자료의 숨은 지시도 살펴봅니다

화면에 보이지 않는 문자나 표시 순서를 바꾸는 문자를 이용해 지시를 숨길 수도 있습니다. 이런 문자는 검토 화면에서 위치를 알아볼 수 있게 표시하고, 왜 사용했는지 확인합니다. 외국어나 이모지 표시에 필요한 경우도 있으므로 무조건 지우지는 않습니다. 반대로 숨은 문자가 없다고 안전한 자료로 판단해서도 안 됩니다.

특정 제품·버전·설정을 쓰는 경우에만 행동을 유도하는 악의적인 지시도 있을 수 있습니다. 예를 들어 AI에게 점검용으로 알려준 내부 정보를 이용해, 해당 환경에서는 보호 기능을 끄거나 불필요한 정보를 수집해야 한다고 유도하는 것입니다. 점검에 필요한 절차처럼 보여도 내부 기술 정보를 역이용하는 지시일 수 있습니다. 외부 인터넷 연결이 없어도 잘못된 점검 결과나 내부 설정 변경으로 이어질 수 있으므로 내부망에서도 살펴봐야 합니다.

제품별 조치 안내 자체가 문제인 것은 아닙니다. 요구하는 행동이 근거와 점검 목적에 맞는지 확인해야 합니다. AI가 실제 작업까지 수행한다면, 설정 변경이나 정보 전송은 조직이 정한 권한과 승인 범위 안에서만 이루어져야 합니다. 자료에 적힌 지시가 곧 작업을 허용하는 근거가 되어서는 안 됩니다.

## 검토한 자료를 파일로도 제공합니다

보안 점검 항목과 판단 기준 자체를 파일로 내려받아 쓸 수 있게 합니다. 어떤 제품·기능에 해당하는지, 무엇을 확인해야 하는지, 어떤 경우에는 판단을 보류해야 하는지와 그 이유를 함께 담습니다.

점검 항목과 판단 이유, 조치 안내, 변경 설명은 한국어로 작성하는 것을 원칙으로 합니다. AI가 참고하는 자료라도 사람이 직접 읽고 확인하며 잘못된 내용을 고칠 수 있어야 하기 때문입니다. 필요한 전문 용어는 짧게 풀어 설명합니다.

웹페이지를 저장하는 기능에 그치지 않고, 사람이 읽는 설명과 도구·AI가 참고할 점검 데이터를 함께 제공합니다. 조직이 필요한 자료를 골라 자신의 컴퓨터 폴더나 내부 저장소에 두고 활용할 수 있어야 합니다. 구체적인 파일 형식이나 프로그램 연결 방법은 실제 구현 단계에서 정할 사항입니다.

외부 자료를 내부망으로 가져올 때는 파일 하나의 크기나 한 번에 옮길 수 있는 전체 용량이 제한될 수 있습니다. 이런 반입 조건에 맞춰 필요한 자료를 가져올 수 있도록, 제품·기능·주제별로 나누어 선택할 수 있게 구성합니다.

처음에는 필요한 범위를 골라 받고, 갱신할 때는 그 범위에서 추가되거나 바뀐 파일만 가져올 수 있도록 합니다. 매번 전체 자료를 다시 내려받고 검토할 필요가 없도록 하되, 함께 필요한 공통 자료가 있다면 표시합니다.

각 파일이나 주제별 묶음에는 다음 정보를 함께 표시하면 좋겠습니다.

- 자료를 제공한 곳과 버전(자료 묶음을 구분하는 번호 또는 이름)
- 언제까지 확인한 정보를 담았는지와 어떤 제품·기능을 포함하는지
- 이전 자료에서 바뀐 내용과 아직 확인하지 못한 부분
- 내부 복사·재배포·수정에 적용되는 이용 조건

제공된 원본과 전달받은 파일이 같은지도 확인할 수 있게 합니다. 필요한 설명은 파일에 포함해, 읽거나 점검에 참고할 때마다 외부 사이트에 로그인하거나 인터넷에 연결할 필요가 없도록 합니다.

## 조직이 받아 내부에서 다시 전달합니다

망분리·폐쇄망에서는 업무용 컴퓨터나 내부 시스템이 외부 인터넷에 자유롭게 접속할 수 없습니다. 이때는 본사·상위 기관·중앙 보안팀 등 관리조직이 자료를 받아 검토하고 내부에 전달할 수 있습니다.

1. 관리조직이 외부에서 배포한 자료와 변경 내용을 내려받습니다.
2. 조직의 절차에 따라 출처·내용과 반입 가능 여부를 확인합니다.
3. 내부 공유 폴더나 문서 저장소에 올리거나, 허용된 메일·메신저로 전달합니다.
4. 이용자는 전달받은 파일을 읽거나 조직이 사용하는 도구·AI에 참고 자료로 제공합니다.

예를 들어 본사가 확인한 자료를 사내 공유 폴더에 두면, 각 부서는 그 파일을 참고해 점검할 수 있습니다. 자료를 이용하는 데 GitHub 계정이나 개발용 저장소가 반드시 필요한 것은 아닙니다.

AI를 활용한다면 조직이 마련한 내부 모델이나 로컬 모델(자신이 관리하는 컴퓨터에서 실행하는 AI)에서 자료를 사용할 수 있어야 합니다. 모델을 새로 만드는 문제가 아니라, 이미 사용하는 환경에 점검 자료를 전달할 수 있게 하자는 제안입니다.

내부의 제품 목록, 질문, 점검 결과를 공개 저장소나 외부 AI로 자동 전송하지 않습니다. 조직에서 덧붙인 내용은 배포받은 원본과 구분하고, 외부에 개선 의견을 보낼 때도 공개할 수 있는 내용인지 먼저 검토합니다. 파일을 내려받을 수 있더라도 조직이 정한 반입 절차는 따라야 합니다.

## 갱신과 정정도 같은 경로로 전달합니다

공개 저장소를 수정해도 이미 내려받은 파일이나 메일 첨부파일은 바뀌지 않습니다. 자료를 배포하는 기관은 변경 내용을 알리고, 내부 관리조직은 새 자료를 검토해 교체한 뒤 이용자에게 안내합니다. 잘못된 자료의 사용을 중단해야 할 때도 같은 경로로 전달합니다.

부분적으로 갱신할 때는 새로 받을 파일뿐 아니라 삭제·교체하거나 사용을 중단해야 할 파일도 안내합니다. 함께 갱신해야 하는 자료를 표시해, 일부 파일만 바꾸면서 잘못된 이전 자료가 남거나 서로 맞지 않는 내용이 함께 쓰이지 않도록 합니다.

원본의 버전과 정보 기준일(언제까지 확인한 내용을 담았는지)에 내부 배포일을 함께 표시합니다. 오늘 받은 파일이라도 지난달까지의 정보만 담고 있을 수 있으므로, 내용을 확인한 날짜와 전달한 날짜를 구분하는 것입니다. 내부에서 자료를 교체하고 정정 안내를 맡을 사람도 정합니다.

자료에 없는 제품이나 아직 반영되지 않은 문제를 "문제없음"으로 처리해서는 안 됩니다. 정보가 부족하거나 오래됐다면 확인할 수 없는 범위를 밝히고 판단을 보류합니다. 내부에 전달되지 않은 최신 공지까지 확인했다고 설명하거나, 부족한 자료를 찾으려고 허용되지 않은 외부 연결을 시도해서도 안 됩니다.

## 담당자와 비용을 확보하고, 업체가 바뀌어도 이어갑니다

자료 조사와 전문가 검토, 쉬운 설명 작성, 갱신·정정과 문의 대응에는 시간·인력·예산이 필요합니다. 무료로 이용할 수 있어도 유지 비용은 듭니다. 공개 기여를 받더라도 반드시 해야 하는 검토와 갱신을 자원봉사자의 여유 시간에만 맡기지는 않는 방향을 제안합니다.

책임 기관 내부에 담당 조직과 전문가를 두고, 외부 업체는 조사·제작·운영을 돕도록 할 수 있습니다. 어떤 자료를 배포하고 오류를 어떻게 바로잡을지 결정할 권한과 책임은 기관 내부에 유지합니다.

업체를 선정할 때는 가장 낮은 가격이나 회사의 운영 기간만으로 판단하지 않습니다. 실제 담당 인력의 역량, 검토·갱신과 오류 대응 경험, 업무를 다른 담당자에게 넘길 준비가 되어 있는지 함께 살펴봅니다. 만든 자료의 양뿐 아니라 이용자가 설명을 이해하는지, 오류가 바로잡히고 갱신이 이어지는지도 평가하면 좋겠습니다.

업체의 폐업·계약 종료나 하청 업체 변경으로 관리가 끊기지 않도록, 책임 기관이 자료·관리 계정·검토 기록·업무 절차와 자료를 수정·배포할 권한을 계속 확보해야 합니다. 새 담당자가 이를 이어받아 관리하고, 자료를 받는 조직에도 갱신·정정 안내를 계속 전달할 수 있어야 합니다.
